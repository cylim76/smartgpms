# smartGPMS 开发方案

版本：0.1
状态：已确认，进入开发
目标平台：门证担当的本地 Windows 电脑

## DAS 页面职责与状态边界

- **DAS 照片页面**：`R_CPM_SEARCH.aspx` / `V_CPM_DETAIL.aspx`，用于 CPMID、箱号、流程状态和 U1/U2/U3/S1 四阶段照片的查询与下载。
- **DAS 门证打印页面**：`R_EGT_TMGERPVIEW.aspx`，用于门证箱号/铅封号查询、查看详细和 DAS 原始打印流程。
- 门证页如果暴露 CPMID，只作为照片记录快速定位的候选值；照片状态和链接必须回照片页面核实。
- `das_process_status=1～5` 是 DAS 照片流程状态，其中 `5.铅封确认` 为完成状态；`business_stage=1～4` 只是照片阶段；本地 `archive_status=5` 只表示照片已完整落盘。
- 首次初始化和日常巡检中，流程状态为 5 但本地照片不完整的记录必须排队下载；详情暂时无照片时按 1/5/15 分钟退避重试。

### 照片落盘规则

- 只下载 DAS 照片详情中 `4.封箱检查`（S1）标签下的全部原图，通常为 3～4 张。
- 目录按 DAS `begin_date` 开始日期组织为 `data/cache/YYYY/MM/CPMID_箱号/`；日期缺失或异常时放入 `data/cache/unknown/CPMID_箱号/`。
- 原图保持 DAS 原始文件名、原始格式和原始字节，不重命名、不压缩、不缩放。
- OCR 旋转中间图和裁剪图放入同一箱号目录的 `_ocr/` 子目录；裁剪图使用 `原图名_container_crop.jpg` 或 `原图名_seal_crop.jpg`。
- 如两个不同照片 URL 给出同一原始文件名，为防止覆盖应停止并记录错误，不得自动改名。

## 1. 项目目标

smartGPMS 用于在打印 DAS 门证前，复用 DAS 已有的四阶段集装箱照片，对门证箱号和铅封号进行本地 OCR 核验，并调用 DAS 原始打印流程。系统不要求司机重复拍照，也不提前下载全部历史照片。

核心目标：

- 一次输入多个箱号；
- 从 DAS 门证详情取得门证箱号和铅封号；
- 通过本地 SQLite 中的索引选择最新有效 CPMID；
- 从 DAS 按需取得四阶段照片；
- 在本机完成方向校正、裁切、OCR、ISO 6346 校验和比对；
- 以绿色、红色、橙色显示核验结论；
- 使用 DAS 原打印业务，记录首次打印、重打、OCR 证据和最后打印时间。

## 2. 总体架构

采用“本地桌面外壳 + 网页式界面 + 后台浏览器会话 + Python 服务”的结构。

```text
smartGPMS Windows 应用
├── 网页式工作台
│   ├── 多箱号输入
│   ├── SSO 登录区
│   └── 六行核验结果表格
├── DAS 会话管理器
│   ├── 手动用户名/密码/OTP 登录
│   ├── 10 分钟探活
│   └── 下载前刷新 SSO → DAS 会话
├── DAS 数据适配器
│   ├── 门证查询及详情字段
│   ├── CPMID 索引同步
│   ├── 四阶段照片下载
│   └── 原始打印流程
├── OCR 适配器
│   ├── RapidOCR 本地 CPU 引擎
│   └── das_photo_ai 预处理/后处理逻辑
└── SQLite / 本地缓存 / 打印证据
```

不使用 Tkinter。网页式界面适合并排展示图片、OCR 文本、状态和打印信息；桌面外壳负责后台浏览器、Windows 凭据和打印能力。

## 3. 界面规格

### 3.1 左侧输入区

- 多行文本框，一行一个箱号；
- Enter 换行，Ctrl+Enter 可触发识别；
- 自动大写、去空格、去重；
- 输入阶段执行格式和 ISO 6346 校验；
- 不提供铅封号输入；
- 不提供照片拖放；
- 所有门证信息和照片均从 DAS 获取。

### 3.2 右侧未登录状态

显示仿照公司 SSO 风格的登录卡：

- 用户名；
- 密码；
- OTP；
- 保存用户名；
- 保存密码；
- 登录按钮；
- 登录错误和会话状态。

登录表单是 smartGPMS 自有界面，后台向真实 SSO 页面提交。浏览器密码自动保存功能不参与。

### 3.3 右侧已登录状态

表格列从左到右：

1. 打印按钮；
2. DAS 业务状态（1～4）；
3. 门证箱号；
4. 门证铅封号；
5. 箱号裁剪图和 OCR 文本；
6. 铅封号裁剪图和 OCR 文本；
7. 最后打印时间。

一屏目标显示六行；超过六行使用滚动或分页。

### 3.4 核验颜色

- 绿色：门证箱号、铅封号与照片 OCR 均一致；
- 红色：存在明确不一致；
- 橙色：找不到记录/照片、OCR 失败、候选不唯一、校验位不清或数据不完整；
- 灰色：排队、下载或识别中。

按钮文字始终为白色。`print_status=0` 显示“打印”，`print_status=1` 显示“重打”。

## 4. SSO 和 DAS 会话

### 4.1 登录

用户在 smartGPMS 中手动输入 OTP。系统不自动申请 OTP。点击登录后：

1. 后台浏览器打开 SSO；
2. 填写用户名、密码和 OTP；
3. 登录成功后打开 DAS `LoginSSO.aspx`；
4. 打开 DAS 目标页面；
5. 确认 DAS 特征元素后将状态设为 ACTIVE。

### 4.2 凭据保存

- 用户名可保存在 SQLite；
- 密码使用 Windows DPAPI 或 Credential Manager 加密，SQLite 只保存引用或密文；
- OTP 永不保存；
- 日志不得输出用户名、密码、OTP、Cookie 或完整会话令牌。

### 4.3 十分钟探活

每十分钟依次访问：SSO 主页、DAS LoginSSO、无副作用 DAS 探测页。使用 `gerp-import/actions/sso_session.py` 的登录页关键词、URL 和 DAS 特征元素判断方法。

状态机：

```text
LOGGED_OUT → LOGGING_IN → ACTIVE → PROBING
                   ↑          ↓
                   └── EXPIRED
```

探活失败后暂停同步和下载，保留待处理任务，界面回到登录卡。重新登录后继续任务。

每次下载照片前再次执行 SSO → LoginSSO → DAS 目标页刷新，不只依赖十分钟前的探活结果。

## 5. CPMID 与业务状态同步

每十分钟在会话有效时执行轻量同步，只保存索引，不默认下载历史照片。

同一箱号可对应多个 CPMID，选择规则：

1. 排除无效/取消记录；
2. 优先已确认存在第四阶段照片的记录（`business_stage=4` 或 `archive_status=5`）；
3. 多条记录都有第四阶段照片时，选择数值最大的 CPMID；
4. 都没有第四阶段照片时也选择数值最大的 CPMID，但核验结果保持待人工确认。

业务阶段：

- 1 / U1：进厂检查；
- 2 / U2：空箱检查；
- 3 / U3：装箱检查；
- 4 / S1：封箱检查。

同步采用水位和重叠窗口：继续扫描新增 CPMID，同时回看近期活动记录以更新阶段。CPMID 允许有空号，不能遇到单个空号即停止。

## 6. 状态 4 后台预处理

观察到记录从 1/2/3 变为 4 后加入预处理队列：

```text
下载四阶段照片
→ 图片方向校正
→ 文字检测
→ 箱号/铅封号候选裁切
→ OCR
→ 保存缓存和结构化 JSON
```

为避免首次运行下载全部历史照片，只自动处理：

- 系统运行后观察到状态转为 4 的记录；或
- 最近 24 小时内、状态 4、未打印的记录。

旧历史记录在用户输入箱号后按需处理。

状态 4 暂无照片时按 1 分钟、5 分钟、15 分钟重试；最终失败显示橙色，并允许核验时再次实时尝试。

OCR 缓存键包含 `cpm_id + 照片 URL/哈希 + 引擎版本 + 模型版本 + 预处理版本`。照片或版本变化后重新处理。

### 6.1 初始化与日常照片巡检

- 仅新电脑首次建库或上次初始化中断时执行初始化：从照片查询页第一行取得最新 CPMID，随后编号逐一递减，要求本次扫描实际取得 500 条有效 CPM 记录；空号不计入 500 条。成功后写入永久完成标记，程序升级不重复初始化。
- 初始化过程中读取每条 CPM 详情；发现第四阶段照片即加入下载队列。
- 本地达到 500 条后，不再重复初始化。每十分钟从最新 CPMID 向前执行日常巡检。
- 日常巡检范围改为按开始日期控制：从最新 CPMID 向前，遇到早于本机当天减 30 天的有效记录即停止，并设置 5000 个编号的安全上限。
- CPM 索引同时保存开始日期、结束日期、产品区分和装箱方式。
- `archive_status=1～4` 对应尚未完整归档的 DAS 阶段；发现第四阶段照片后下载全部阶段原图。
- 全部照片保存成功后设置本地 `archive_status=5`。状态 5 巡检只检查本地文件；文件缺失时重新从 DAS 下载修复。
- 照片目录使用 `CPMID_箱号` 格式；后台照片任务始终按 CPMID 从新到旧执行。
- 用户主动核验不受 30 天限制；本地没有箱号映射时先从门证打印页查询箱号并取得 CPMID，再按该 CPMID 下载照片。
- 核验界面采用本地优先加载：已有照片、OCR 裁剪和缩略图先显示，门证箱号/铅封号随后从 DAS 实时补齐。门证数据不做长期预缓存，因为通常要等出厂当天由 GERP 发送到 DAS。
- 后台 OCR 同步生成小尺寸列表缩略图并保存数据库路径；原图仍只用于点击放大和证据查看。
- 本地不存在待核验箱号时，不扩大初始化窗口，也不从门证页面或新 CPMID 游标猜测映射；系统在 DAS 照片下载页面按箱号精确查询检查序号。多个检查序号按“有第四阶段照片优先、完成状态优先、CPMID 较大优先”选择，然后执行原有下载和 OCR 流程。
- 自动同步和后台照片下载仅在本机时间 07:00–23:59 运行；00:00–06:59 暂停后台作业。人工核验不受后台时段限制。

## 7. OCR 与裁剪

OCR 层采用接口化实现：

- 初版使用 RapidOCR + ONNX Runtime CPU；
- 复用 `das_photo_ai` 的箱号/铅封号候选、校验位、预处理和后处理规则；
- 后续可切换 PaddleOCR，不修改业务和界面。

必须保存：

- OCR 原始文字；
- OCR 置信度和文字框；
- 实际识别的校验位；
- 计算出的校验位；
- 建议修正值；
- 来源照片和阶段；
- 旋转角度和裁剪坐标；
- 引擎、模型、预处理版本。

程序不得把计算校验位伪装成照片实际识别结果。

方向校正尝试 0°、90°、180°、270°，以格式、校验和置信度选择最佳方向；裁剪图保留适当上下文，并允许查看原图。

## 8. 门证查询和打印

门证查询页：

`http://das.china.lge.com:7005/eGate/tm/R_EGT_TMGERPVIEW.aspx?t3_menuid=EGT340103`

工作流：

1. 输入箱号查询；
2. 精确匹配结果行；
3. 读取该行“查看详细”的实际 `__doPostBack` 目标；
4. 在保持 `__VIEWSTATE`、`__EVENTVALIDATION` 的页面中触发；
5. 捕获详情/打印页；
6. 读取 `lbl_container_no` 和 `lbl_seal_no`；
7. 核验后调用 DAS 原打印动作。

`dgMain$ctl03$ctl00` 中的行号是动态的，禁止写死。必须从精确匹配行读取当次 PostBack 参数。

实际打印前仍需在已登录环境验证查询控件、弹窗、打印按钮和业务状态更新机制。

## 9. SQLite 数据模型

### 9.1 `cpm_records`

- `cpm_id` 主键；
- `container_no`；
- `begin_date`、`end_date`；
- `das_status_text`；
- `business_stage`；
- `latest_stage_code`；
- `photo_count`；
- `is_valid`；
- `print_status`：0 未打印、1 已打印；
- `print_count`；
- `last_printed_at`；
- `ocr_status`：pending/processing/complete/failed；
- `first_seen_at`、`last_seen_at`、`last_checked_at`。

`container_no` 建索引但不唯一。

### 9.2 `photo_cache`

保存 CPMID、阶段、URL、文件哈希、原图路径、下载时间和缓存状态；以 CPMID + URL 唯一。

### 9.3 `ocr_cache`

保存照片、目标类型、原始 OCR JSON、最佳候选、裁剪路径、旋转角度、置信度、引擎/模型/预处理版本和处理时间。

### 9.4 `print_history`

采用追加式历史，不覆盖：

- CPMID、箱号；
- 门证箱号、门证铅封号；
- 照片 OCR 箱号、铅封号；
- 匹配结论；
- OCR 完整快照；
- 证据裁剪图路径；
- 操作人；
- 首次打印/重打；
- 重打原因；
- 打印时间；
- DAS 打印结果。

### 9.5 `app_settings`、`session_state`、`sync_state`、`background_jobs`

分别保存非敏感设置、会话状态、CPMID 水位/探活时间和可恢复的后台任务。

## 10. 打印事务

只有打印命令成功提交后才执行：

1. 固化本次 OCR 和裁剪证据；
2. 新增 `print_history`；
3. `print_count += 1`；
4. `print_status = 1`；
5. 更新 `last_printed_at`；

## 10.1 通门证同步与打印缓存

- 门证列表页日期条件对应“计划出厂日期”，后台仅同步当天计划出厂记录；
- 独立 `gate_passes` 表保存门证元数据，不能把门证直接覆盖到可能重复的 CPM 记录；
- 计划出厂时间用于 PDF 目录、文件名前缀及当天有效性判断；
- 同箱多条门证按 `planned_departure_at`、`sequence_no`、`gate_pass_no` 倒序选择；
- PDF路径为 `data/gatepass/YYYY/MM/计划出厂时间(yyyyMMddHHmmss)_箱号_门证号.pdf`；
- 数据变化或数据库 PDF 路径与计划出厂时间生成的目标路径不一致时，旧 PDF 标记失效并重新生成；生成成功后更新数据库路径并删除被替换的旧 PDF；
- 服务端生成 PDF，客户端浏览器通过系统打印对话框把 PDF 发送到客户端电脑的打印机；
- PDF缓存保留60天，数据库元数据继续保留；
- 计划出厂日期不是当天时，页面醒目标记，并在打印前执行独立的二次确认。

### 数据表 `gate_passes`

- `gate_key`、门证号、页面序号；
- 申请日期、计划/实际出厂时间；
- 箱号、铅封号、状态及其他列表字段；
- 数据指纹、PDF路径、PDF缓存状态及生成/清理时间。
6. 按钮改为“重打”。

如果只能打开浏览器打印对话框而无法确认是否提交，则增加用户“打印完成确认”，用户取消时不能修改打印状态。

绿色允许直接打印；红色或橙色打印前必须二次确认并记录原因。重打保留原历史并新增记录。

## 11. 缓存和证据

普通缓存（原图、临时裁剪、可重建 OCR）按时间和磁盘容量清理。已经用于打印的 OCR 快照和证据图复制到独立证据目录，不受普通缓存清理影响。

缓存清理和证据保留周期做成配置项。删除动作必须记录日志。

## 12. 分阶段验收

1. **页面验证**：确认已登录 DAS DOM、PostBack、详情字段和打印动作。
2. **登录与会话**：手动 OTP 登录、探活、失效回登录区、凭据安全保存。
3. **索引同步**：CPMID/箱号/阶段增量更新，重复箱号选择正确。
4. **状态 4 处理**：自动下载、方向校正、裁剪、OCR和幂等重试。
5. **门证核验**：多箱号、六行表格、绿红橙判定、图片放大。
6. **打印审计**：打印/重打、状态 0→1、最后打印时间和不可变历史。
7. **Windows 交付**：异常恢复、缓存治理、CPU 性能、安装和启动验证。

## 13. 已知前置验证

无会话访问门证页会跳转到 `Logout.aspx?LogoutMsgType=SESSIONLOST`。开发打印适配器前，需要在用户手动登录的有效会话中完成一次只读页面结构检查；在此之前不得根据猜测执行实际打印。

## 14. 2026-09-22 实机验证记录

已使用有效 SSO/DAS 会话完成只读 DOM 采集，确认：

- SSO 登录字段：`USER`、`LDAPPASSWORD`、`OTPPASSWORD`；登录按钮：`loginSsobtn`；
- 门证查询箱号框：`txt_s_container_no`；查询按钮：`btnSearch`；

- 详情页打印按钮：`btnPrint`，原始动作是 `window.print()`；
- 门证查询按钮属于 ASP.NET UpdatePanel 异步回发，自动化必须等待 `dgMain` 出现精确箱号，不能只等待页面 load 事件。
- smartGPMS 使用独立、无界面的 Edge 用户数据目录执行 SSO、DAS 查询和门证 PDF 生成；普通同步不操作担当正在使用的浏览器。
- 因 DAS 的 `btnPrint` 本质为 `window.print()`，无界面浏览器不能完成系统打印。用户点击打印后，后台按 DAS 打印样式生成临时 PDF，再由当前可见的 smartGPMS 页面打开打印预览并唤起系统打印窗口。
- 打印预览窗口提供显式“打印”按钮作为浏览器自动唤起失败时的备用入口；之后仍由用户确认“打印成功”，取消时不修改 `print_status`，也不写打印历史。
- 临时门证 PDF 只在待确认期间保留，确认或取消后立即删除；未完成任务和异常退出残留文件在 10 分钟后自动清理。
