# smartGPMS 实施状态

## 2026-09-24 Windows WinSW 服务模式（0.14.0）

- 新增 `install_service.bat` 与 `uninstall_service.bat`，使用 WinSW 2.12.0 将 smartGPMS 注册为 Windows 自动延迟启动服务；
- WinSW 从官方 GitHub Release 下载并执行 SHA-256 校验，服务以隐藏窗口、单 Uvicorn worker、失败自动重启方式运行；
- 安装时只开放域/专用网络的 TCP 8765 入站规则，卸载时同步移除规则，但保留数据库、照片、PDF、日志及 Python 环境；
- 删除旧的 `run_server.bat` 前台服务器入口；Windows 只保留 `run_win.bat` 本机模式以及服务安装/卸载入口；
- Windows 服务默认使用 `LocalSystem`，服务 DPAPI 与桌面用户隔离；无法解密另一身份的旧密码时保留用户名并要求重新保存密码，不再导致页面初始化失败；
- 数据库原有的中断恢复会在进程重启时把遗留的 `running` 后台任务恢复为 `pending`，避免强制停止服务后任务永久卡住。
- Windows 服务入口独立端口冒烟测试通过，Ruff 检查通过，自动测试 `115 passed`。

## 2026-09-24 照片分批扫描与独立 OCR 工作线程（0.13.4）

- DAS 监装记录按每批 20 箱设置调度检查点；批次之间若门证同步已到期，先检查当天门证，再继续下一批照片记录；
- SSO/DAS 页面查询、照片详情读取和原图下载继续共用单一浏览器线程，避免并发操作同一会话；
- 原图全部落盘后释放浏览器线程，裁剪、旋转和 RapidOCR 转入独立的单 CPU 工作线程；OCR 期间门证同步和其他 DAS 查询可以继续调度；
- 同一时间只允许一个后台 OCR 箱号，避免 CPU/内存争抢；正在 OCR 时，门证 PDF 任务仍可优先执行；
- 安全退出会等待当前 OCR 箱号完成，未领取的照片任务保留为待处理，下次启动继续；
- Ruff 全量检查通过，自动测试 `110 passed`。

## 2026-09-24 Linux systemd 安装模式（0.13.2）

- Linux `setup_linux.sh` 在完成 Python、Playwright 和 OCR 依赖安装后，按当前项目绝对路径、当前 Linux 用户及数据目录动态生成并注册 `smartgpms.service`；
- 服务安装后通过 `systemctl start/stop/restart/status smartgpms` 统一管理，并通过 `journalctl -u smartgpms` 查看日志；
- systemd unit 明确使用服务器模式、单 Uvicorn worker、失败自动重启和开机自动启动；
- 移除 Linux `run.sh` 与 `run_server.sh`，避免前台运行入口和 systemd 服务入口混用；
- 安装脚本必须由最终运行 smartGPMS 的普通 Linux 用户执行，只在安装系统包和注册 unit 时调用 sudo。

## 2026-09-24 独立后台同步周期（0.13.1）

- 当日门证同步保持每 10 分钟执行一次；
- DAS 监装记录及照片状态扫描调整为每 20 分钟执行一次；
- 两类同步由同一个后台工作线程串行运行，并在各自任务完成后重新计算下一次执行时间，不会出现上一轮未结束又叠加下一轮的情况；
- 已排队的照片下载、缩略图、裁剪和 OCR 仍按箱号逐个连续处理，20 分钟周期只控制 DAS 数据发现与状态扫描。

## 2026-09-24 桌面与服务器关闭边界（0.13.0）

- Windows `run_win.bat` 为单机桌面模式：关闭专用窗口后停止接收新任务，等待当前箱号完成，再关闭 DAS/SSO 会话和本机服务。
- Windows WinSW 服务与 Linux systemd 服务为服务器模式：任意客户端关闭页面都不会影响服务端。
- 待处理但尚未开始的后台队列不会在桌面关闭时丢失，下次启动后继续处理。
- 服务器模式不提供由浏览器页面触发的服务关闭能力；服务生命周期交由 Windows 服务管理器、systemd 或终端管理。

# 0.5.0 CPM 初始化与照片归档巡检

- 本地记录不足 500 条时，从 DAS 最新 CPMID 开始递减扫描，直到累计 500 条有效记录。
- 达到 500 条后切换为日常巡检：状态 1～4 查询第四阶段照片，状态 5 校验本地文件并自动修复缺失。
- 完整照片归档状态独立于 DAS 业务阶段，使用 `archive_status=5` 表示照片已落盘。
- 新下载照片保存到 `data/cache/CPMID_箱号/`，任务按最新 CPMID 优先执行。
# 0.5.1 30天日常巡检窗口

- 初始化达到500条后，日常同步从最新 CPMID 倒查到“当天减30天”的开始日期边界。
- CPM 元数据新增产品区分和装箱方式；开始、结束日期继续同步。
- 用户主动核验不受30天限制；缺少本地映射时优先从门证页解析 CPMID，再读取照片详情。
# 0.5.2 重复箱号 CPMID 选择

- 多条候选都有第四阶段照片时选择数值最大的 CPMID；都没有时也取最大值并保留人工确认状态。

# 0.8.6 门证 PDF 打印流程

- 后台不再在无界面 DAS 浏览器中直接调用 `window.print()`，改为按 DAS 详情页打印样式生成临时 PDF。
- 前台预先打开 smartGPMS 打印窗口，PDF 生成后显示预览并尝试唤起系统打印；同时保留可见的“打印”按钮。
- 只有用户确认打印成功后才写入打印状态、打印时间和 OCR 证据；选择“尚未成功”不修改业务数据。
- 打印任务的临时 PDF 在确认、取消或超时后自动删除，异常退出的残留文件也会自动清理。

# 0.8.7 异常打印确认原因

- DAS 无门证时只显示“确定”，提示到 GERP 发送门证，并禁止继续进入打印流程。
- 门证查询异常时同样禁止打印，要求重新核验。
- 箱号或铅封号不一致时，确认框分别显示门证值和照片 OCR 值；没有照片或无法识别时显示为“无”。
- 异常核验继续打印必须输入人工确认原因，空原因不能提交。

# 0.8.8 核验行实时阶段

- 核验结果行按箱号接收结构化进度，不再统一显示“正在查询/下载识别”。
- 状态列依次显示查询箱号记录、查询门证、查询照片、下载照片、RapidOCR 识别和核验比对。
- 下载及 OCR 阶段显示当前照片序号，例如“下载四阶段照片 2/4”。
- 门证、箱号 OCR、铅封 OCR 和其他照片单元格同步显示各自当前阶段。

# 0.9.0 独立数据库与增量同步边界

- 取消从旧 `das_photo` 数据库自动导入，smartGPMS 只使用自己的 SQLite 数据库；旧版本已经导入且没有照片、OCR 或打印证据依赖的孤立元数据会执行一次安全清理。
- 日常新增扫描从 DAS 最大 CPMID 向下进行，以“本次同步开始前的本地最大 CPMID”或“开始日期早于当天减 30 天”任一条件作为停止边界，不因中途遇到任意已有记录而提前停止。
- 30 天窗口内只向 DAS 重新查询状态小于 5 或本地照片意外缺失的记录；状态 5 且照片完整的记录直接跳过，按保留策略主动清理的照片不会自动回下载。
- 同步日志统一显示 `扫描 / 新增 / 更新 / 跳过 / 下载`，五项均按集装箱数量统计，不按照片张数统计。

# 0.9.1 四阶段照片完整性与 OCR 原图隔离

- 数据库新增 `downloaded_photo_count`，`photo_count` 改为记录 DAS 当前返回的第四阶段原图数；下载数量按不同原图统计，不把旋转图和裁剪图重复计数。
- 只有第四阶段至少 3 张原图已经落盘，才将照片归档状态标记为完成；少于 3 张会在后续 10 分钟巡检中继续查询，补充出现的新照片。
- 一张原图只要识别为箱号照片，该原图产生的全部旋转、裁剪和 OCR 候选都不能再参与铅封号选择。
- 启动时自动清除旧数据中“箱号与铅封号使用同一原图”的错误铅封 OCR，并把对应箱号安排为待重新识别。

- 多项原因与其他补充文字合并保存到打印历史的确认原因字段。

## 0.9.4 DAS 原图命名与后台队列修正

- 从 DAS 照片链接文字提取 `F` 编号，第四阶段原图按 `F编号.扩展名` 保存；没有 `F` 编号时才使用服务器 URL 文件名。
- 已缓存的 `S1_...` 原图在该箱号下次进入照片处理时迁移成对应的 `F...` 文件名，并同步更新数据库路径。
- CPM 同步不再取消尚未执行的照片/OCR任务；状态 5 且照片缺失的记录直接排队，由后台任务获取详情和下载照片。
- 下一轮 CPM 同步从上一轮完成后的 10 分钟开始计算，留出连续处理照片队列的时间。
- 同步日志显示“后台处理排队”，实际完成时单独显示 CPMID 和本地原图张数，避免把排队数量误认为已经下载完成。

## 0.9.5 本地优先显示与打印加速

- 后台下载及 OCR 时同步生成列表缩略图，`photo_cache.thumbnail_path` 保存缩略图路径；列表优先直接读取小图，不再为每次请求重复解码大原图。
- 点击核验后先整批返回本地照片、OCR 和历史状态，再逐箱从 DAS 刷新门证；门证尚未返回期间明确显示后台查询状态且禁止打印。
- 不长期预取门证。打印时仅短时复用刚刚核验、当前页面内容再次校验一致的门证详情页；页面已切换、超过时限或箱号不一致时自动重新查询 DAS。
- 自动清理原图时同时删除对应缩略图并清空数据库路径，避免遗留无用文件。

## 0.9.6 缺失箱号按需查询照片页面

- 保持首次初始化 500 条和日常最新 CPMID 同步范围不变；不通过扩大初始化下载量解决历史箱号问题。
- 用户核验的箱号不在本地数据库时，进入 DAS 照片下载页面，在 `txtCntrNo` 输入箱号并触发 `btnSearch`，解析 AJAX 查询响应中的检查序号（CPMID）。
- 人工核验查询不受 30 天维护窗口限制；照片页面使用精确箱号和宽日期范围查询历史记录。
- 同一箱号匹配多个 CPMID 时，优先选择实际存在第四阶段照片的记录；条件相同则选择状态完成记录，再选择更大的 CPMID。
- 查到 CPMID 后写入本地数据库，并继续使用原有照片下载、缩略图、OCR 和门证核验流程。
- 门证打印页面不再用于推测 CPMID；原有向最新游标递增盲查 300 个 CPMID 的后备逻辑已取消。
